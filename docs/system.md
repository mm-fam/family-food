# Poppy 2.0 system reference

The app is named **Poppy 2.0** (the family's name for its earlier AI project). The repo and URL keep the `family-food` name so existing home-screen links keep working.

_Last updated: Nov 3 2026 (api 35: meal votes follow the meal, pack sizes, make more, idea-email fix; api 12: Cart Jobs, so a parent's phone can start a cart build or check; api 11: Products tab, In-cart tag, aisles, Amazon store)_

## Purpose
A shared phone app where anyone in the family adds what we need, picks dinners, and taps staples, with Claude behind it closing the loop from receipts and filling store carts. Design goal from day one: **it must never become a chore or go stale.** Automation (receipts, "probably due", draft lists) does the upkeep, not the family.

## People and roles
| Who | Role |
|---|---|
| Mom | Runs household food. Final say on menus, carts, what's bought. |
| owner | Builder and admin. Owns the repo, Sheet, Apps Script deployment, Chrome sessions. |
| Kids | App users. Adds land as `requested`; a parent approves. Adding a meal's ingredients (Missing for meals, a meal card's "Add N to the List", the day sheet) is parents only (api 38); kids see the ingredients but no add button. |
| Claude | Operator: receipt ingest, cart building, catalog upkeep, Review questions, code changes. |

## Stores
- **Giant Eagle (GE):** kid lunches, snacks, everyday dinners. Curbside/delivery. myPerks rewards account.
- **Whole Foods (WF):** ordered through Amazon. Premium items, produce, specialty (Nounos yogurt, Creminelli salami, brie bites, pizza dough).
- **Target (TGT):** toiletries, personal care, paper and household. Drive Up / pickup about once a month (online orders also ship). Mostly non-food.
- **Amazon (AMZ):** fourth store (app plumbing since api 11; cart building not started). Like Target, never part of `Either`.
- **Deliveries, not stores (api 31):** `WG` = Wildgrain (frozen bread, pastries and pasta; subscription box every 30 days; goes in the freezer) and `BB` = Bleu Box (local prepared-meal delivery; weekly menu of small plates, large plates, desserts, extras; mostly heat and eat). Items with these as `store` never go on the List (backend `addToList` skips them: missions' out, meal ingredients), are never Probably due, never in a cart, In store or `Either`. The app shows them with a 🧊 instead of +, the item screen says where they come from, meal ingredients show them as 🧊 instead of Need, Shop has a 🧊 Deliveries pill, and Meals has a 🧊 **On hand from deliveries** card (delivery items whose latest Stock sighting isn't out / waste / 0). A delivery is ingested like a receipt: order email → Receipts (store WG/BB, order_ref `WG <order #>`) → Items; Stock is logged when it arrives (a parents' "Did the box come?" card).
- `Either` = either grocery store (GE or WF), whichever order is next. Never Target or Amazon.

## Architecture
```
phones (GitHub Pages, PWA)  --POST-->  Apps Script web app  -->  Google Sheet "Poppy 2.0 (app data)"
                                                                       ^
                       Claude (Sheets/Gmail connectors, Chrome) -------+  receipts, carts, review
```
| Piece | Where |
|---|---|
| App | `mm-fam/family-food` (public repo), served at https://mm-fam.github.io/family-food/. Plain HTML/JS/CSS, no build: `index.html`, `app.js`, `styles.css`, `manifest.webmanifest`, `icons/` (Poppy 2.0 logo, rounded-square robot tile: 180 apple-touch full-bleed for iPhone, 192 + 512 with transparent rounded corners, 512 maskable at 70% on a matching teal gradient for Android, `poppy-logo.png` 320 shown on the unlock and "Who's this?" screens). |
| Config | `config.js` holds `API_URL` (the Apps Script `/exec` URL). Not a secret. |
| Backend | `apps-script/Code.gs` in the repo; the live copy is in the Sheet's Apps Script. Deployed as Web app, Execute as Me, access Anyone. A push to `main` that changes Code.gs deploys it automatically (deploy job of the **Checks** GitHub workflow, after the smoke tests pass; clasp; runbook §4). `?action=version` (no passcode) returns the live `api`. |
| Passcode | Script Property `FAMILY_PASSCODE`. Checked on every request. Never put it in the repo or in project docs. |
| Data | Google Sheet "Poppy 2.0 (app data)" in the owner's Drive |

### App behavior
- **Always light mode** (owner, Nov 2): the app ignores the phone's light/dark setting (`color-scheme: light`, no dark-mode styles), so every phone looks the same.
- Four tabs, evenly spaced: **List, Shop, Meals, Inbox** (Inbox was Q&A, before that Ask; its internal id stays `ask`). **List** shows a count of active items (green; orange when a parent has kids' requests waiting); **Inbox** shows open cards for you plus, for parents, approvals waiting. First launch asks passcode + "Who's this?" (stored on the device). While the first state loads (after Unlock, and on every return visit) a loading screen shows the logo, a spinner and "Checking the passcode…" / "Getting the list…", adds a "server is waking up" line after 4 s, and offers **Try again** if the load fails (a wrong saved passcode goes back to the passcode form). **Saved copy (Nov 2, speed):** the last state is kept on the phone (localStorage `ff_state`, ignored after 3 days, cleared by a wrong passcode), so a return visit shows the List at once with a small "Updating…" pill above the tab bar until fresh state arrives; the loading screen only shows on a first visit. Backend api 33 reads each tab once per state (it used to read Review, Settings, Receipts and Plan several times), remembers the time zone and date formatting, and returns `state.timing` (ms per tab read, `dailyCards`, `total`) to find slow spots.
- **List** = **what's still open** (reworked Nov 2: carts live on the Carts screen, so the List answers "what do we still have to deal with?"). Top to bottom: Home Screen tip, ⏳ Use soon, kids' requests, then a **summary line** ("**N need a cart** · N in carts · N later"), then **🍽 Missing for meals** (kept small, Nov 2: it was taking attention from the List): ingredients of meals planned in the next 7 days that aren't on the List or Later, weren't bought or had in the last 3 days, and weren't seen at home in the last 7 days. **Since api 54:** today's meals drop off once their slot has passed on the phone's clock (breakfast after 10, lunch after 2 pm, snack after 5 pm, dinner after 8 pm), and **pantry staples** (Items `pantry` = Y) are assumed on hand unless their latest sighting in 14 days is low / out. With something missing, a compact card: one row per meal, item names first (tap → item screen), day · meal under them, **Add** (`addMeal`; parents only since api 38) and **Have**, which opens a sheet for that meal: every ingredient starts ✅ have; tap one to flip it to 🛒 need; **🫙 Always have** marks it a pantry staple. Save = Stock `some` for the haves, `addMeal` for the needs, `itemSave` pantry for any changed flag. **🔎 Have the girls check N** (parents, api 55) at the top of the card sends every item not already on an open mission to the kids as 🔎 mission cards (`missionsAsk`, split fewest-open-first, "🍽 For the meal plan: go check the …"); items out for checking show "🔎 <kid>" after their name and the card says "🔎 N out for checking". Answers work like any mission: Some / Plenty clears the item, A little / Out puts it on the List as a request. With nothing missing, one quiet line "🍽 Nothing missing for meals". Either way a small **N unchecked ›** link opens a sheet of planned meals with no ingredients set up (each → its meal card / Edit meal); the card only checks linked ingredients. Then **one section, On the List · N** (owner, Nov 2 ~10:20 am: the separate Needs a cart / In carts sections read as one blurred list): every active row by aisle, rows already in (or on the way to) an online cart carrying their 🛒 / ⏳ tag. Open/Close all sits by the title, **🛒 Put N in carts** (parents) on the right, and one row of pills **All · 🛒 Needs a cart · 🍽 Meals · 🧺 Stock** (single choice; Needs a cart = in no online cart, incl. ⚠ Not added; Meals = added for a still-planned meal or used in one planned in the next 7 days). The summary's "N in carts ›" opens the Carts screen. Then **⏸ Later · N** (dashed, folded): we need it, just not this order; each row says "back <day>" or "no date", with **Need it now**. Rows show a store dot, **Only at <store>**, cart tag, qty, note, meal tag and who asked. Everything starts folded each time the app opens. A row that leaves the List stays crossed out ~6 s with **Undo**. No check-off at home: tapping a row opens the item screen. **⏳ Use soon (api 22)** sits above everything else on the List: perishables with `shelf_days` from the day before their last good day (bought date = newest of Items last_bought and a List row marked bought, + shelf_days) until 3 days after it, unless the item is back on the List or someone said it's used up or tossed. Each row: name, "good through tomorrow" / "last good day today" / "probably past it · still there?", **Used it** (Stock `out`) · **Tossed** (Stock `waste`) · **Still good** (Stock `some` + `expires` = today + 3, so it comes back in 2 days) (no points: reconciling scores through missions only). Anything tossed 2+ times in 60 days gets one parents' card (type `waste`, ⚖ Decisions): Buy fewer / Buy less often / It's fine.
- **🛒 In store** (List header; everyone incl. kids): pick a store (GE / WF / Target / All); rows by aisle with checkboxes. Every row shows except ones **only** another store carries; rows usually bought elsewhere say "usually <store>". **A virtual cart** (Nov 1): tapping a row puts it in the cart: the row is `bought` at once (note "in the cart in store (<name>)") and leaves the list for good; no crossed-out rows and no taking it back out there. A folded **🛒 In the cart** card at the bottom lists what's in the cart today, for everyone shopping together; "N in the cart · N to go" on top. Something put in by mistake is added again from Shop.
